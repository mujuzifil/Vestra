# Stage 18.8A — Component Library Report

## Objective
Build a reusable, token-based UI component library so no portal invents its own styling.

## Locations
- `frontend/components/ui/` — low-level primitives
- `frontend/components/design-system/` — cross-cutting concerns (toast)
- `frontend/components/common/` — higher-level marketing/composite components refactored to use tokens

## Components delivered

| `Card` | Card shell with header/title/description/content/footer |
| `Input` | Text inputs |

| `Select` | Native select with chevron |

### Cross-cutting
| Component | Purpose |
|-----------|---------|
| `design-system/toast.tsx` | Unified `sonner` wrapper with VESTRA token styling |

### Refactored common components
- `Container`, `PageHero`, `FormField`, `Breadcrumb`, `EmptyState`, `CTASection`, `SectionHeader`
- Existing `components/ui/empty-categories.tsx`, `api-error.tsx`, `retry-button.tsx`, `skeleton-card.tsx`

## Variant system
All primitives use `class-variance-authority` (CVA) for type-safe variants and `tailwind-merge` + `clsx` for class composition.
