# Stage 18.8A — Developer Guidelines

## Naming conventions
- Components: PascalCase (`Button.tsx`, `PageHeader.tsx`)
- Hooks: camelCase prefixed with `use`
- Utilities: camelCase
- Token CSS variables: kebab-case

## Token usage
Always use design tokens instead of hardcoded values:

```tsx
// ✅ Correct
<button className="bg-secondary-500 text-white hover:bg-secondary-600">

// ❌ Incorrect
<button className="bg-[#70c050] text-white hover:bg-[#5aa33d]">
```

## Component usage
Import from the shared UI library:

```tsx
import { Button } from "@/components/ui/button";
import { Card, CardHeader, CardTitle, CardContent } from "@/components/ui/card";
```

## Layout usage
- Public pages: use default root layout
- Account pages: wrapped by `CustomerLayout` via `app/account/layout.tsx`
- Distributor pages: wrapped by `DistributorLayout` via `app/distributor/layout.tsx`

## Motion
Use motion utilities from `frontend/styles/motion.css`:

```tsx
className="transition-colors-base hover:-translate-y-1"
```

Respect `prefers-reduced-motion`; do not add one-off long animations.

## Icons
Use `lucide-react` only. For consistent sizing/color, use the `Icon` wrapper:

```tsx
import { Icon } from "@/components/ui/icon";
<Icon icon={Bell} size="md" color="muted" />
```

## Do's and Don'ts
- Do reuse `Card`, `Button`, `Badge`, `Input`, `EmptyState`
- Do keep business logic unchanged during UI standardization
- Do run `npx tsc --noEmit` and `npm run lint` after changes
- Don't hardcode hex colors in new components
- Don't introduce duplicate icon libraries
- Don't add custom one-off animations

## Validation
Before committing, ensure:
- `npx tsc --noEmit` passes
- `npm run lint` passes
- No new hardcoded hex colors introduced
