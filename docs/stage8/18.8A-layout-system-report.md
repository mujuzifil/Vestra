# Stage 18.8A — Layout System Report

## Objective
Standardize page layout structures across the Public Website, Customer Portal, and Distributor Portal.

## Layout components

### `frontend/components/layout/public-layout.tsx`
Wraps public/marketing pages with:
- `Navbar`
- `Footer`
- `WhatsAppFloat`
- Main content area

Used implicitly via `RootLayoutClient`. Public pages retain the global navigation and footer.

### `frontend/components/layout/customer-layout.tsx`
New account-portal layout added via `frontend/app/account/layout.tsx`:
- Sticky sidebar (desktop) / drawer (mobile)
- Navigation links: Dashboard, Orders, Profile, Photo, Security, Password, Preferences, Addresses, Activity, Notifications
- Mobile hamburger toggle
- Sign-out action

### `frontend/components/layout/distributor-layout.tsx`
Extracted from `frontend/app/distributor/layout.tsx`:
- Authentication/role guard preserved
- Renders `DistributorSidebar`
- Consistent content padding and background

## Distributor sidebar updates
- Replaced non-token classes (`border-border`, `text-muted`, `bg-white`) with token equivalents
- Replaced `tailwindcss-animate` classes with design-system `animate-slide-right`

## Consistency rules applied
- All portals use `--topbar-height: 64px` and `--navbar-height: 88px`
- Sidebar sticky offset matches navbar height
- Content backgrounds use `--surface-page`
- Cards use `--surface-card`
- Mobile drawers use the same animation and z-index strategy

## Status
✅ Public, customer, and distributor layouts standardized.
