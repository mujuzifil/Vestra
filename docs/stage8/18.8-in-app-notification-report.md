# Stage 18.8 — In-App Notification Report

## Implementation

In-app notifications use Laravel's built-in `notifications` table (`Illuminate\Notifications\DatabaseNotification`).

## Key Files

- `backend/database/migrations/2026_07_24_300001_create_notifications_table.php`
- `backend/app/Notifications/SystemNotification.php`
- `backend/app/Services/NotificationDispatcherService.php`
- `backend/app/Http/Controllers/Api/V1/NotificationController.php`
- `frontend/components/notifications/notification-bell.tsx`
- `frontend/app/notifications/notifications-page-client.tsx`

## Features

- Laravel database notifications with `type`, `data`, `read_at`
- REST endpoints:
  - `GET /api/v1/notifications`
  - `GET /api/v1/notifications/unread`
  - `PUT /api/v1/notifications/{id}`
  - `PUT /api/v1/notifications/read-all`
  - `DELETE /api/v1/notifications/{id}`
- Notification bell dropdown in navbar
- Dedicated notifications page with read/delete actions

## Frontend Components

- `NotificationBell` — navbar unread count + quick preview
- `NotificationsPageClient` — full notification list

## Outcome

Customers and distributors can view and manage in-app notifications. Unread counts update through React Query invalidation.
