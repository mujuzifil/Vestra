# Stage 18.8 — Template Management Report

## Implementation

Templates store channel-specific content and variable definitions per event key.

## Key Files

- `backend/app/Models/NotificationTemplate.php`
- `backend/app/Services/NotificationTemplateService.php`
- `backend/database/migrations/2026_07_24_300002_create_notification_templates_table.php`
- `backend/database/seeders/NotificationTemplateSeeder.php`
- `backend/app/Filament/Resources/NotificationTemplateResource.php`
- `backend/app/Http/Controllers/Api/V1/Admin/NotificationTemplateController.php`

## Schema

| Field | Purpose |
|-------|---------|
| `event_key` | Unique identifier (e.g. `order.created`) |
| `subject` | Email subject template |
| `email_body` | HTML email body |
| `sms_body` | SMS body |
| `in_app_body` | In-app message body |
| `channels_json` | Enabled channels |
| `variables_json` | Available variable descriptions |
| `is_active` | Enable/disable template |
| `version` | Template versioning |

## Management Interfaces

- Filament: `System → Notification Templates`
- REST API: `/api/v1/admin/notifications/templates`

## Fallback

If a template is missing, `NotificationTemplateService::resolve()` returns a transient fallback template so events never fail silently.

## Outcome

Administrators can create, update, and deactivate notification templates without deploying code.
